# Skill: todo-extractor

扫描代码库，提取所有 `TODO` / `FIXME` / `HACK` / `XXX` / `NOTE` 注释，生成一份结构化的待办事项报告，帮助开发者追踪未完成的工作和技术债。

## 这个 skill 做什么

1. 在指定目录（默认当前工作目录）下搜索代码文件中的特殊标记注释。
2. 按标记类型（TODO/FIXME/HACK/XXX/NOTE）分类统计。
3. 为每条记录收集：文件路径、行号、标记类型、注释正文、上下文（所在函数/类/组件名，如可推断）。
4. 过滤掉依赖目录（`node_modules`、`.git`、`build`、`oh_modules`、`*.d.ts` 产物等）。
5. 输出一份 Markdown 报告，包含汇总统计表和按文件分组的明细列表。

## 工作流

### Step 1: 确定扫描范围

- 如果用户指定了目录或文件，使用该范围。
- 否则默认扫描当前工作目录（不递归进入忽略目录）。
- 默认忽略目录（除非用户明确要求包含）：
  - `node_modules`、`.git`、`.hg`、`.svn`
  - `build`、`out`、`.idea`、`.vscode`
  - `oh_modules`、`entry/src/ohosTest/ets/build`（HarmonyOS 产物）
  - 任何 `.gitignore` 中列出的目录（可简单识别常见项）

### Step 2: 执行搜索

使用 `grep` 工具搜索以下标记（正则，大小写不敏感，匹配注释行）：

```
\b(TODO|FIXME|HACK|XXX|NOTE)\b
```

- 对每个匹配结果，记录：文件路径、行号、整行内容。
- 用 `include` 参数限制文件类型，避免二进制文件：常见源码后缀 `.ts`、`.ets`、`.js`、`.jsx`、`.tsx`、`.java`、`.kt`、`.py`、`.go`、`.rs`、`.c`、`.cpp`、`.h`、`.hpp`、`.cs`、`.rb`、`.php`、`.swift`、`.m`、`.mm`、`.vue`、`.svelte`。
- 若不确定项目语言，可先 `glob` 一次看看主导后缀，再决定 `include`。

### Step 3: 解析与去重

对每条原始匹配：

1. **提取标记类型**：取行中第一个匹配的 `TODO|FIXME|HACK|XXX|NOTE`（大写）。
2. **提取正文**：去掉行注释符 `//`、`#`、`/*`、`*`、`<!--`、`-->` 和标记本身后的剩余文本，trim 首尾空白。若正文为空，标记为 `(无说明)`。
3. **处理多行块注释**：若 `/* ... */` 注释跨多行，只把含标记的那一行作为一条记录，不合并相邻行。
4. **去重**：同一文件同一行只保留一条。
5. **可选：推断上下文**：通过读取该文件、向前回溯找到最近的 `function`/`def`/`class`/`struct`/`@Component`/`export` 等声明，记录"所属符号"。若 30 行内找不到，记为 `(顶层)`。此步可选，避免过度耗时。

### Step 4: 生成报告

输出一份 Markdown 报告，**直接打印到对话**（不写文件，除非用户要求保存）。报告格式见下方模板。

### Step 5: 收尾

- 在报告末尾给出简短的"建议处理优先级"：FIXME 通常优先于 TODO，HACK 提示需要重构。
- 不主动修改任何源码。
- 如果用户随后要求"帮我把这些 TODO 处理掉"，再切换到实际编码模式。

## 报告模板

```markdown
# 待办事项报告

扫描范围：`<目录路径>`
扫描时间：<YYYY-MM-DD HH:MM>
匹配文件数：<N> ｜ 总记录数：<M>

## 汇总统计

| 标记 | 数量 | 含义 |
|------|-----:|------|
| TODO | <n> | 计划做但未做 |
| FIXME | <n> | 已知缺陷，需修复 |
| HACK | <n> | 临时方案，待重构 |
| XXX   | <n> | 警告/需关注 |
| NOTE  | <n> | 说明性备注 |

## 明细（按文件分组）

### `path/to/file.ets`

| 行 | 类型 | 内容 | 上下文 |
|---:|------|------|--------|
| 42 | TODO | 支持暗色模式 | `build()` |
| 108 | FIXME | 列表为空时崩溃 | `loadData()` |

### `path/to/another.ts`

| 行 | 类型 | 内容 | 上下文 |
|---:|------|------|--------|
| 7 | HACK | 绕过权限检查 | `checkAuth()` |

## 建议优先级

1. **FIXME**（<n> 条）— 已知缺陷，建议尽快修复。
2. **HACK**（<n> 条）— 临时方案，应在下个迭代重构。
3. **TODO**（<n> 条）— 按业务价值排序处理。
```

## 关键注意事项

1. **大小写不敏感但保留原样**：搜索时大小写不敏感（`todo`、`Todo` 都算），但报告里展示的标记统一用大写，正文保留用户原始写法。
2. **不要匹配变量名**：只匹配出现在注释上下文中的标记。简单规则：同行需包含注释符（`//`、`#`、`/*`、`*`、`<!--`）才计入。避免把 `const TODO = 1` 这类代码误判。若拿不准，宁可收录并在正文标注"疑似代码"。
3. **尊重忽略目录**：产物目录、依赖目录一律跳过，避免噪音。
4. **不修改源码**：本 skill 只读取和报告，不写文件、不改代码。
5. **报告要可操作**：每条记录必须带文件路径和行号，格式为 `file:line`，方便用户跳转。在对话中引用时使用 `file_path:line_number` 格式。
6. **空结果也要回应**：若一条都没找到，明确告诉用户"未发现 TODO/FIXME/HACK/XXX/NOTE 标记，代码看起来很干净"，不要静默。
7. **大仓库控制成本**：若匹配超过 500 条，只展示汇总统计和前 100 条明细，并提示用户用更窄的范围或按目录分批扫描。
