# todo-extractor 优化计划

> 针对 `skills/todo-extractor/SKILL.md` 的优化方案。原 skill 可用但存在误判风险、字段缺失、流程脱节等问题。本计划按优先级列出问题与改法，作为 v2 的实现依据。

## 优化目标

1. **降低误判**：避免把变量名、字符串字面量误判为 TODO。
2. **提取更有价值的字段**：指派人、日期、优先级、关联 issue。
3. **流程前后一致**：把"注释符约束"真正落到搜索正则，而不是只在注意事项里口头要求。
4. **控制成本**：上下文推断要有明确的触发条件，不要默认对每条记录读文件。
5. **更实用**：支持"只看本次改动"（结合 git）、可保存输出、可按类型过滤。

---

## P0 — 必须修复（影响正确性）

### P0-1 正则与"注释符约束"脱节，导致误判
- **问题**：Step 2 用 `\b(TODO|FIXME|HACK|XXX|NOTE)\b`，会匹配 `const TODO = 1`、字符串里的 `"fixme"`、文件路径 `xxx.ts`。注意事项第 2 条口头要求"同行需含注释符"，但正则没体现，执行者（LLM）可能直接照搬正则导致误判。
- **改法**：搜索正则改为要求标记位于注释上下文中。按语言分两组正则：
  - 行注释类（`//`、`#`、`--`、`;`）：`(^|\s)(//|#|--|;)\s.*(TODO|FIXME|HACK|XXX)\b`
  - 块注释类（`/* */`、`<!-- -->`）：`(\*|<!--).*\b(TODO|FIXME|HACK|XXX)\b`
  - 一次 grep 用 `(//|#|--|;|\*|<!--)\s.*\b(TODO|FIXME|HACK)\b` 覆盖大多数。
- **额外**：去掉默认 `XXX`（三字母太易误判，如 `xxx.ts`、域名），改为可选标记。`NOTE` 默认不纳入"待办"（它是说明性备注，语义不符），单独分组或默认关闭。

### P0-2 "匹配文件数 / 总记录数"获取方式未交代
- **问题**：报告模板要求"匹配文件数"，但 Step 2~3 只说"对每条匹配记录"，没说如何聚合不重复文件数。grep 返回的是行级匹配，需在 Step 3 之后做一次去重聚合。
- **改法**：在 Step 3 增加明确动作："按文件路径去重得到 `matchedFiles` 集合，`len(matchedFiles)` 即匹配文件数"。流程闭环。

### P0-3 上下文推断成本失控
- **问题**：Step 3.5"可选：读取该文件回溯找声明"，在 500 条记录时 = 读 500 次文件，成本极高且没说触发阈值。
- **改法**：上下文推断改为"按需触发"——仅当匹配总数 ≤ 50 时默认开启；> 50 时默认关闭并提示用户可显式要求。明确说明用 `read` 工具按 `offset` 读取目标行号上方窗口（如 offset=line-20, limit=25）来回溯声明。

## P1 — 应该改进（影响实用性）

### P1-1 缺少指派人 / 日期 / 优先级字段提取
- **问题**：常见格式 `TODO(alice):`、`FIXME(@bob):`、`TODO(2024-01-01)`、`FIXME [P0]` 都没提取。这是待办报告最有用的字段。
- **改法**：在 Step 3 增加结构化字段解析，从标记后紧跟的括号/方括号里提取：
  - `TODO(name):` → assignee = `name`
  - `TODO(@name):` → assignee = `@name`
  - `TODO(YYYY-MM-DD)` → due = 日期
  - `FIXME [P0|P1|P2]` → priority = 级别
  - `TODO #123` / `TODO(gh-123)` → issue = `123`
  - 提取失败的字段留空，不报错。
- **报告模板**：明细表新增 `指派`、`优先级`、`关联` 列（按需展示，全空则省略列）。

### P1-2 优先级建议静态且会列 0 条
- **问题**："FIXME 优先于 TODO" 是写死的，若仓库只有 TODO，建议里仍会列 `FIXME（0 条）`，啰嗦。
- **改法**：建议段改为动态生成——只列出实际存在且 > 0 的标记类型；若仅 TODO，建议简化为一句话；同时根据"是否有过期日期/高优先级标签"调整建议。

### P1-3 缺少"只看本次改动"模式（结合 git）
- **问题**：代码评审时最关心"本次 PR 新增了哪些 TODO"，原 skill 不支持。
- **改法**：新增一个可选模式：当用户说"只看新增的"、"本次改动里的"、"diff 里的"时，用 `git diff --name-only` + `grep` 限定到改动文件，或直接 `git diff -U0 | grep` 提取新增行中的标记。明确此模式的触发词与命令。

### P1-4 缺少"按类型过滤"参数
- **问题**：用户可能只想看 FIXME，或想排除 NOTE。原 skill 无逃生口。
- **改法**：在 Step 1 增加可配置项：`include`（默认 `TODO,FIXME,HACK`，不含 XXX/NOTE）、`exclude`（用户可指定排除某些类型）。触发词里识别"只看FIXME"、"排除NOTE"等。

### P1-5 输出保存选项不清
- **问题**：报告说"不写文件除非用户要求"，但没说保存到哪、用什么文件名格式。
- **改法**：明确：用户要求保存时，默认写入 `<工作目录>/TODO-REPORT-<YYYYMMDD>.md`；并说明可用 `write` 工具。

## P2 — 可选增强（锦上添花）

### P2-1 缺少真实示例输入输出
- **问题**：纯文字描述，执行时易跑偏。
- **改法**：在 skill 末尾加一个"示例"小节，给一段含各种格式的 mini 源码 + 对应的期望报告输出，作为锚点。

### P2-2 缺少 git blame / 新旧度信息
- **问题**：知道 TODO 是上周加的还是 3 年前加的对优先级判断很有用，但 git blame 成本高。
- **改法**：标记为"可选高级模式"，用户显式要求"带时间"时，对匹配行调用 `git blame -L <line>,<line> --date=short <file>` 取提交日期。> 50 条时默认关闭。

### P2-3 多语言注释符覆盖不全
- **问题**：只列了 `//`、`#`、`/*`、`*`、`<!--`，漏 SQL/Lua 的 `--`、汇编 `;`、Ruby `=begin`。
- **改法**：补全注释符清单（低优先级，因主流语言已被覆盖）。

### P2-4 大仓库阈值偏低
- **问题**：500 条就截断到前 100，可能过早。
- **改法**：阈值改为可配置，默认提到 800，截断展示 150，并提示按目录分批。

## 不改的地方（确认保留）

- frontmatter 格式（`name` + `description`）正确，保留。
- 触发词多的风格保留（有利于命中）。
- "只读不改源码"的核心约束保留。
- 直接打印到对话、不默认写文件的策略保留。
