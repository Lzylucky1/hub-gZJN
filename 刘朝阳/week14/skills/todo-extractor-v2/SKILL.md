# Skill: todo-extractor-v2

扫描代码库注释，提取 `TODO` / `FIXME` / `HACK`（可选 `XXX` / `NOTE`）标记，解析指派人、日期、优先级、关联 issue，生成一份结构化待办报告。相比 v1，重点优化：误判更少、字段更全、支持本次改动模式、成本可控。

## 这个 skill 做什么

1. 在指定目录（默认当前工作目录）搜索**注释中**的特殊标记（非变量名/字符串字面量）。
2. 按标记类型分类，并解析每条的指派人 / 截止日期 / 优先级 / 关联 issue。
3. 过滤依赖与产物目录（`node_modules`、`.git`、`build`、`oh_modules` 等）。
4. 支持两种范围模式：**全量扫描**与**只看本次 git 改动**。
5. 输出 Markdown 报告（汇总表 + 按文件分组明细 + 动态优先级建议），默认打印到对话，按需保存。

## 工作流

### Step 1: 确定模式与配置

读取用户意图，确定以下配置：

- **范围模式**：
  - **全量模式**（默认）：扫描指定目录，默认当前工作目录。
  - **本次改动模式**：当用户说"只看新增的"、"本次改动里的"、"diff 里的"、"PR 里的"时启用。
- **标记集 `include`**：默认 `TODO,FIXME,HACK`。
  - `XXX` 默认**不**纳入（三字母易误判，如 `xxx.ts`、域名）。用户说"含XXX"才加入。
  - `NOTE` 默认**不**纳入（它是说明性备注，语义不符）。用户说"含NOTE"才加入，且单独分组。
- **排除 `exclude`**：用户可指定排除某类（如"排除HACK"）。
- **上下文推断**：默认仅当匹配总数 ≤ 50 时开启"所属符号"推断；> 50 默认关闭以控成本，可由用户显式要求"带上下文"开启。
- **保存**：默认不写文件。用户要求"保存/导出/写文件"时，写入 `<工作目录>/TODO-REPORT-<YYYYMMDD>.md`。

**默认忽略目录**（除非用户明确要求包含）：`node_modules`、`.git`、`.hg`、`.svn`、`build`、`out`、`.idea`、`.vscode`、`oh_modules`、`*.d.ts` 产物目录。

### Step 2: 执行搜索（关键：正则要求注释上下文）

**核心改进**：搜索正则要求标记位于注释上下文中，避免匹配变量名/字符串字面量。

#### 全量模式

用 `grep` 工具，正则（大小写不敏感，覆盖主流语言的行注释与块注释行）：

```
(//|#|--|;|\*|<!--)\s.*\b(TODO|FIXME|HACK)\b
```

- `include` 参数限定源码后缀：`.ts`、`.ets`、`.js`、`.jsx`、`.tsx`、`.java`、`.kt`、`.py`、`.go`、`.rs`、`.c`、`.cpp`、`.h`、`.hpp`、`.cs`、`.rb`、`.php`、`.swift`、`.m`、`.mm`、`.vue`、`.svelte`、`.sql`、`.lua`。
- 若不确定语言，先 `glob` 探一次主导后缀。
- 若 `include` 含 `XXX`，正则里的标记组追加 `XXX`；含 `NOTE` 同理追加 `NOTE`。

#### 本次改动模式（git）

优先用 git diff 直接抓新增行中的标记，避免扫描未改动文件：

1. 先取改动文件清单：`git diff --name-only`（或 `git diff --cached --name-only` 看暂存区，按用户语境）。
2. 对每个改动文件用 `git diff -U0` 输出，在 `+` 开头的新增行里匹配标记。
3. 若上面不便操作，退化为：用 `grep` 搜索，但 `path` 限定为改动文件清单中的路径。

### Step 3: 解析与聚合

对每条原始匹配：

1. **提取标记类型**：取行中第一个匹配的 `TODO|FIXME|HACK|XXX|NOTE`，规范化为大写。
2. **提取正文**：去掉注释符（`//`、`#`、`--`、`;`、`/*`、`*`、`<!--`、`-->`）与标记本身后的剩余文本，trim 首尾空白。空则记 `(无说明)`。
3. **结构化字段解析**（从标记后紧跟的括号/方括号/`#` 中提取，失败留空不报错）：

   | 原文格式 | 字段 | 示例 |
   |---|---|---|
   | `TODO(alice):` | assignee=`alice` | `TODO(alice): 重构缓存` |
   | `TODO(@bob):` | assignee=`@bob` | `TODO(@bob): 改样式` |
   | `TODO(2024-12-31):` | due=`2024-12-31` | `TODO(2024-12-31): 下线旧API` |
   | `FIXME [P0]` | priority=`P0` | `FIXME [P0]: 内存泄漏` |
   | `TODO #123` / `TODO(gh-123)` | issue=`123` | `TODO #123: 见issue` |
   - 同一标记可同时带多个，如 `TODO(alice) [P1] #42:` → assignee=alice, priority=P1, issue=42。

4. **去重**：同一文件同一行只保留一条。
5. **聚合文件数**：按文件路径去重得到 `matchedFiles` 集合，`len(matchedFiles)` 即"匹配文件数"。
6. **上下文推断（按 Step 1 配置）**：开启时，用 `read` 工具按 `offset=<line-20>, limit=25` 读取该行上方窗口，回溯最近的 `function`/`def`/`class`/`struct`/`@Component`/`export` 声明作为"所属符号"。30 行内找不到记 `(顶层)`。

### Step 4: 生成报告

输出 Markdown 报告，**直接打印到对话**（除非用户要求保存，则用 `write` 写到 Step 1 约定的路径）。报告格式见下方模板。

### Step 5: 收尾

- **动态优先级建议**：只列出实际存在且 > 0 的标记类型；若仅 TODO，建议简化为一句话。若存在"过期日期"或 `[P0]`，在建议中突出。
- **空结果**：一条都没找到时，明确回复"未发现 TODO/FIXME/HACK 标记，代码看起来很干净"，不静默。
- **不主动改源码**。用户随后要求处理这些 TODO 时，再切换到编码模式。

## 报告模板

```markdown
# 待办事项报告

扫描范围：`<目录或 git diff>`
模式：<全量 | 本次改动>
扫描时间：<YYYY-MM-DD HH:MM>
匹配文件数：<N> ｜ 总记录数：<M>
（若上下文模式不同/带 blame，标注：上下文=开/关 ｜ blame=开/关）

## 汇总统计

| 标记 | 数量 | 含义 |
|------|-----:|------|
| TODO  | <n> | 计划做但未做 |
| FIXME | <n> | 已知缺陷，需修复 |
| HACK  | <n> | 临时方案，待重构 |
（NOTE 若纳入则单独一节"说明性备注"，不计入待办总数）

## 明细（按文件分组）

### `path/to/file.ets`

| 行 | 类型 | 指派 | 优先级 | 关联 | 内容 | 上下文 |
|---:|------|------|--------|------|------|--------|
| 42 | TODO  | alice | P1 | #42 | 支持暗色模式 | `build()` |
| 108 | FIXME |      | P0 |    | 列表为空时崩溃 | `loadData()` |

> 若"指派/优先级/关联"三列全表为空，则省略这三列，只保留 行/类型/内容/上下文。

### `path/to/another.ts`

| 行 | 类型 | 内容 | 上下文 |
|---:|------|------|--------|
| 7 | HACK | 绕过权限检查 | `checkAuth()` |

## 建议优先级

1. **FIXME**（<n> 条，其中 P0 <x> 条）— 已知缺陷，建议尽快修复。
2. **HACK**（<n> 条）— 临时方案，应在下个迭代重构。
3. **TODO**（<n> 条，其中过期 <x> 条）— 优先处理过期项，其余按业务价值排序。
（仅列出实际 > 0 的类型）
```

## 关键注意事项

1. **正则必须含注释符**：用 `(//|#|--|;|\*|<!--)\s.*\b(MARK)\b`，确保标记在注释里，避免 `const TODO = 1` 误判。拿不准时宁可收录并在正文标注 `(疑似代码)`。
2. **大小写**：搜索大小写不敏感（`todo`/`Todo` 都算）；报告标记统一大写，正文保留原写法。
3. **XXX 默认关闭**：太短易误判，仅用户要求时开启。
4. **NOTE 语义不同**：是说明性备注，非待办，默认不纳入；纳入时单独分组，不计入待办总数。
5. **不修改源码**：只读和报告。
6. **可操作**：每条带 `文件路径:行号`，对话引用用 `file_path:line_number`。
7. **大仓库控成本**：匹配 > 800 条时，只展示汇总统计和前 150 条明细，并提示"按目录分批扫描或缩窄范围"。上下文推断在 > 50 条时默认关闭。
8. **可选 blame 模式**：用户显式要求"带时间/带 blame"时，对匹配行用 `git blame -L <line>,<line> --date=short <file>` 取提交日期，写入"日期"列。> 50 条默认关闭，提示成本较高。

## 示例（执行锚点）

**输入片段**（`src/utils.ts`）：

```typescript
// TODO(alice) [P1] #42: 支持暗色模式
export function applyTheme() { /* ... */ }

// FIXME: 列表为空时崩溃
function loadData() { /* ... */ }

const HACK_BYPASS = true; // 不是注释中的 HACK，应被忽略
```

**期望报告（节选）**：

```markdown
### `src/utils.ts`

| 行 | 类型 | 指派 | 优先级 | 关联 | 内容 | 上下文 |
|---:|------|------|--------|------|------|--------|
| 1 | TODO | alice | P1 | #42 | 支持暗色模式 | `(顶层)` |
| 5 | FIXME | | | | 列表为空时崩溃 | `loadData()` |
```

（第 7 行的 `HACK_BYPASS` 因不在注释上下文中被正确忽略。）
